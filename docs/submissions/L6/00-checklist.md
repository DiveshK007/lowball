## The rules other builders were rejected for

These are not our inventions; they are the failure modes to design against.

### 1. Feedback must be a Google Sheet link

A `FEEDBACK.md` file on its own is **rejected**. The Sheet is the primary
artifact: it is timestamped, it is not editable by us after the fact in a way a
reviewer can't see, and it shows the raw responses. `FEEDBACK.md` summarises and
links to it — it never replaces it.

- [ ] Sheet created, link sharing set to "anyone with the link can view"
- [ ] Link in `docs/FEEDBACK.md`
- [ ] Link in `VITE_FEEDBACK_FORM_URL` so the app shows it after every bid
- [ ] Verified the link opens in a logged-out/incognito window

### 2. Real users only — no scripted wallets, one verifiable tx hash each

Every row in `docs/USERS.md` must carry a transaction hash that the Preprod
indexer confirms is a **`placeBid` on our live contract**. A wallet address alone
proves nothing; anyone can paste one.

`ops/src/verify-users.ts` enforces this and rejects, with a reason:
transactions that do not exist, that touch a different contract, that are on our
contract but are not `placeBid`, and malformed hashes. **`USERS.md` is generated
from its output — never written by hand.** A hand-maintained table is precisely
the unverifiable evidence the rule targets.

> The simulated bidders used to prove the accumulator (`drop-soldout`,
> `drop-proof`) are **house-run and must never be counted as users.** They exist
> as contract evidence, are clearly labelled as proofs in the gallery, and their
> wallet is ours.

- [ ] Every user row regenerated via `verify-users.ts`
- [ ] Distinct wallet count ≥ 70
- [ ] No house wallet in the list

### 3. No AI-rewritten feedback — keep testers' own words

Quote responses verbatim, including the awkward and unflattering ones. Tidying
grammar makes every response sound like one voice, which is the tell. Summarise
in *our* words under "themes"; never rewrite theirs.

- [ ] Quotes copied verbatim from the Sheet, typos and all
- [ ] Negative and confused responses included, not filtered
- [ ] Any paraphrase clearly marked as ours, not presented as a quote

### 4. Current demo video, real screenshots, no placeholders

- [ ] Video shows the **current** build: multi-drop gallery, 1AM or Lace connect,
      sealed bid, privacy panel, reveal, sold-out path, receipts
- [ ] README screenshots are real captures of the deployed site
- [ ] No lorem ipsum, no `TODO`, no stock art anywhere in the submission
